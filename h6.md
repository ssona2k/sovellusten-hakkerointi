<img width="1070" height="843" alt="Screenshot From 2026-09-30 16-38-17" src="https://github.com/user-attachments/assets/9cf215c1-ac4f-42d7-9c21-920f432c9995" />

The camera's main program is missing all five of the standard security protections that modern programs normally have. This program runs as `root` and listens on the network, so this matters.
F-1 on its own, is not a vulnerability. It's a missing layer of defense. But because `main` runs as root and is reachable over the network, any memory bug in it (like the buffer overflows in F-2 and F-3) would be much easier to turn into full control of the camera.

Also the camera is built out of old building blocks that nobody maintains anymore.

  - uClibc 0.9.33.2 — the C library every program links against. This version is from 2012 and the project is effectively dead.
  - hostapd v2.7-devel — the software that runs the camera's Wi-Fi access point. v2.7 is from 2018, and -devel means it's not even a finished release, it's a development snapshot.

I didn't try to exploit anything myself, so I can't prove the camera can be broken into. But the missing protections and outdated components make that much easier for anyone who tries. If I used this camera, I'd keep it on a separate network and turn off remote access.
The most surprising part wasn't the camera. It was how fast with the right tools, finding these weaknesses took, which means attackers can do it just as quickly.
